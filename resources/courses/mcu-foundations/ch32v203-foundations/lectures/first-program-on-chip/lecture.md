## 第一个程序：认识单片机，让代码跑起来 {#introduction}

欢迎来到单片机入门课程。

如果你以前从来没有接触过单片机，不知道 MCU、GPIO、烧录这些词是什么意思，也完全没有关系。

这门课程不会要求你一开始就记很多概念。

我们会从最简单的问题开始：

> 单片机到底是什么？

然后亲手完成第一件事：

> 修改一行程序，让开发板上的 LED 按照你的想法闪烁。

完成这一课后，你不需要已经会写复杂的 C 语言程序，也不需要知道单片机内部的所有结构。

你只需要建立最基本的认识：

**我们写的程序，可以真正控制一块现实中的硬件。**

---

## 什么是单片机 {#what-is-mcu}

在开始写程序之前，我们先认识今天真正要控制的东西：

**单片机。**

你每天使用的很多设备里面，其实都有类似单片机的芯片。

例如：

- 智能台灯；
- 电饭锅；
- 电子秤；
- 遥控器；
- 小型机器人；
- 智能门锁；
- 无人机；
- 各种传感器设备。

这些设备为什么能够按照程序工作？

因为里面通常有一颗负责“思考和控制”的芯片。

我们可以暂时把单片机理解成：

> **一台装在一颗芯片里的小型计算机。**

它没有电脑那么强大，也不会拿来运行大型游戏。

但它非常擅长做一件事情：

> **按照我们写好的程序，控制电子设备。**

例如：

```text
检测一个按键
      ↓
判断按键有没有被按下
      ↓
打开一盏灯
```

或者：

```text
读取传感器
      ↓
根据传感器数据进行判断
      ↓
控制电机运动
```

甚至以后我们的机器马会做：

```text
看到路线
    ↓
判断应该往哪里走
    ↓
控制舵机
    ↓
改变运动方向
```

这些事情背后，都需要一颗单片机不断执行程序。

---

## 单片机和电脑有什么区别 {#mcu-and-computer}

你现在正在使用的电脑也可以运行程序。

那么：

> 为什么还要使用单片机？

可以用一个简单的例子理解。

如果我们只想控制：

* 一颗 LED；
* 一个按键；
* 一个蜂鸣器；
* 一个舵机；

显然没有必要给它配一整台电脑。

我们只需要一颗体积很小、耗电很低、可以长期运行程序的芯片。

这就是单片机非常适合做的事情。

可以简单对比：

```text
电脑
├─ 功能很多
├─ 性能很强
├─ 可以运行 Windows
├─ 可以打开浏览器
└─ 可以运行各种大型软件

单片机
├─ 很小
├─ 功耗低
├─ 功能更加专一
└─ 非常适合直接控制硬件
```

因此在机器人、电器、仪器、传感器等设备中，经常可以看到单片机。

---

## MCU 又是什么 {#what-mcu-means}

以后你还会经常看到一个缩写：

**MCU**

MCU 的英文是：

**Microcontroller Unit**

中文通常翻译为：

**微控制器**

在我们的课程里，可以暂时认为：

```text
MCU ≈ 微控制器 ≈ 单片机
```

所以以后看到：

```text
MCU 程序
MCU 开发
MCU 工程
```

不用害怕。

说的就是：

> 给单片机写程序。

---

## 我们使用哪一颗单片机 {#our-mcu}

这套机器马教学平台使用的单片机型号是：

**CH32V203C8T6**

名字看起来很长。

第一课完全不需要把这个型号背下来。

你现在只需要知道：

> CH32V203C8T6 就是这块开发板上负责运行我们程序的核心芯片。

以后我们会慢慢认识它拥有的各种功能。

例如：

* 控制普通引脚；
* 读取按键；
* 产生 PWM；
* 使用串口通信；
* 读取模拟信号；
* 控制传感器。

这些现在都不用学。

这一课，我们只让它完成最简单的一件事情：

**控制一颗 LED。**

---

## 芯片和开发板不是一回事 {#chip-and-board}

这里非常容易混淆。

我们手里拿着的整块电路板，叫：

**开发板**

而开发板上的其中一颗芯片，才是：

**单片机。**

可以把它理解成：

```text
开发板
│
├─ CH32V203 单片机   ← 负责运行程序
├─ LED
├─ 按键
├─ 接口
├─ 电源电路
└─ 其他电子元件
```

开发板的作用，就是把单片机和一些常用硬件连接在一起，让我们更方便地学习和实验。

所以我们真正做的事情是：

```text
给单片机写程序
        ↓
单片机运行程序
        ↓
单片机控制开发板上的硬件
```

这一课，被控制的硬件就是：

**LED。**

---

## 单片机到底能控制什么 {#what-can-mcu-do}

一颗单片机可以和很多电子设备连接。

例如：

```text
                LED
                 ↑
按键  →       单片机       →  蜂鸣器
                 ↓
              显示屏
                 ↓
               舵机
```

它既可以：

**接收信息**

例如：

* 按键有没有按下；
* 传感器测到了什么；
* CCD 看到了什么；
* 电脑发来了什么数据。

也可以：

**控制设备**

例如：

* LED 亮还是灭；
* 蜂鸣器响不响；
* 舵机转多少；
* 屏幕显示什么。

以后机器马的很多功能，本质上都可以看成：

```text
获得信息
   ↓
程序判断
   ↓
控制硬件
```

这也是为什么学习单片机不仅是在“学习一颗芯片”。

我们实际上是在学习：

> **怎样通过程序控制现实世界中的电子设备。**

---

## 程序怎样控制硬件 {#program-controls-hardware}

现在产生一个新的问题：

> 单片机怎么知道我们希望它做什么？

答案就是：

**程序。**

例如我们可以写一个程序，让它不断执行：

```text
等待一会儿
↓
改变 LED 状态
↓
等待一会儿
↓
再次改变 LED 状态
↓
继续重复
```

结果就是：

```text
亮
↓
灭
↓
亮
↓
灭
↓
……
```

于是我们看到 LED 在闪烁。

所以：

> LED 并不是自己决定闪烁的。

真正决定它行为的是：

**运行在单片机里的程序。**

## 我们用什么语言写程序 {#c-language}

这套课程主要使用：

**C 语言**

来编写单片机程序。

如果你以前已经学过一点 C 语言，会比较容易上手。

如果还不熟，也没有关系。

课程不会先花很多节课把整本 C 语言重新讲一遍。

我们会在真正需要某个语法时再学习它。

例如今天你会看到：

```c
static unsigned int blink_period_ms = 500U;
```

这一整行现在完全不要求你全部理解。

第一课只需要知道：

> 其中的 `500U` 是一个数字，我们马上会修改它。

以后再慢慢学习：

* 什么是变量；
* 什么是函数；
* 什么是 `if`；
* 什么是数组；
* 什么是结构体。

## 电脑里的代码还不能直接控制开发板 {#code-to-board}

现在假设我们已经在电脑中写好了：

```c
static unsigned int blink_period_ms = 500U;
```

是不是开发板上的 LED 马上就会改变？

当然不会。

因为现在程序还在：

**电脑里。**

而真正负责控制 LED 的是：

**开发板上的 CH32V203。**

所以我们需要把程序从电脑送到单片机中。

整个过程可以先简单记成：

```text
在电脑上写程序
       ↓
编译程序
       ↓
生成单片机程序
       ↓
烧录到开发板
       ↓
单片机开始运行
       ↓
LED 发生变化
```

这就是你今天第一次要完成的完整过程。

---

## 什么叫编译 {#what-is-build}

我们写的是 C 语言。

但是单片机并不能直接理解：

```c
RHS_Teaching_ToggleLed();
```

这样的文字。

因此电脑需要使用一个工具，把我们写的 C 程序转换成单片机能够执行的程序。

这个过程叫：

**编译。**

第一课不需要研究编译器内部是怎么工作的。

先把它想象成一个：

**翻译器**

即可。

```text
我们能读懂的 C 语言
        ↓
      编译器
        ↓
单片机能执行的程序
```

在 Studio 中，你会看到：

**Candidate Build**

和：

**Firmware Build**

两个名字。

我们先理解最简单的区别。

---

## Candidate Build 是一次快速检查 {#candidate-build}

你修改学生代码以后，首先会运行：

**Candidate Build**

它可以暂时理解成：

> **先检查一下我刚才写的代码有没有明显问题。**

例如你原来应该写：

```c
static unsigned int blink_period_ms = 1000U;
```

如果不小心把某些符号删除了，程序可能就无法编译。

Candidate Build 会帮助你尽早发现问题。

所以以后可以形成一个习惯：

```text
修改代码
   ↓
先检查
```

而不是：

```text
修改代码
   ↓
马上往开发板里面烧
```

---

## 为什么修改以后还要看 Diff {#review-diff}

Candidate Build 通过以后，Studio 还会让你查看：

**Diff**

这个词现在也不用记它的英文含义。

你可以把它理解成：

> **看看我刚才到底改了哪些地方。**

例如本课只希望修改：

```text
500U
```

变成：

```text
1000U
```

那么 Diff 应该非常简单。

它的意义是帮助你确认：

> 我修改的是不是自己真正想修改的东西？

这是一个非常好的工程习惯。

以后代码变复杂以后尤其重要。

---

## 什么叫 Firmware Build {#firmware-build}

Candidate Build 只是快速检查学生正在修改的实验代码。

真正要生成可以放进单片机中的完整程序，还需要：

**Firmware Build**

Firmware 中文通常叫：

**固件**

第一次接触时，可以简单理解成：

> **最终准备放进单片机运行的程序。**

所以：

```text
Candidate Build
```

可以理解为：

> 先检查我的实验代码。

而：

```text
Firmware Build
```

可以理解为：

> 把整个单片机程序真正准备好。

现在不需要知道它们内部到底有什么区别。

只需要知道：

**检查代码**和**生成完整程序**不是同一步。

---

## 什么叫烧录 {#what-is-flash}

完整程序准备好以后，还有最后一个重要问题：

> 它现在仍然在电脑里，怎样进入单片机？

这就需要：

**烧录。**

英文界面里经常会看到：

**Flash**

烧录的作用可以简单理解成：

```text
电脑中的程序
      ↓
    WCH-Link
      ↓
CH32V203 单片机
```

WCH-Link 是电脑和单片机之间的一个工具。

它帮助我们把程序写进芯片。

因此：

> 编译成功并不等于程序已经进入开发板。

只有完成烧录以后，单片机才拿到了新的程序。

---

## 为什么还要观察 LED {#observe-hardware}

烧录成功以后，还有最后一步：

**观察真实硬件。**

例如你告诉程序：

```text
每隔 1 秒改变一次 LED 状态
```

那么最终应该真的看到：

```text
亮
↓
大约 1 秒
↓
灭
↓
大约 1 秒
↓
亮
```

如果真的出现了这个现象，那么我们才完成了整条链路：

```text
我修改了代码
     ↓
代码通过检查
     ↓
完整程序生成成功
     ↓
程序烧进芯片
     ↓
芯片开始执行
     ↓
LED 按预期变化
```

这才是单片机学习特别有意思的地方：

> 电脑屏幕上的代码，最后真的变成了现实世界里的动作。

```c

{
    RHS_Teaching_DelayMs(blink_period_ms);
    RHS_Teaching_ToggleLed();
}
```

这一部分会不断重复。

```text
再改变一次 LED 状态

```

## 今天只修改一个数字 {#edit-parameter}

找到：

```c
static unsigned int blink_period_ms = 500U;
```

第一课暂时不解释：

```text
static
unsigned int
```

分别是什么。

你只需要关注：

```text
500U
```

我们可以把：

```c
500U
```

改成：

```c
1000U
```

这里的单位是：

**毫秒，ms**

你应该见过：

```text
1000 ms = 1 s
```

因此修改成：

```c
1000U
```

以后，程序大约会：

```text
等待 1 秒
↓
改变一次 LED 状态
↓
再等待 1 秒
↓
再次改变 LED 状态
```

于是 LED 会慢慢闪烁。

## 为什么第一课只改一个数字 {#why-simple}

有些同学可能会觉得：

> 第一课只改一个数字，好像太简单了。

但这是故意的。

因为今天真正要学习的并不是：

> 怎样写一个复杂程序。

而是第一次弄清楚：

> **我修改的代码，是怎样真正跑到单片机上的。**

如果第一课一下同时修改很多代码：

```text
引脚
函数
配置
延时
变量
硬件
```

一旦 LED 没有工作，我们反而不知道是哪一步出了问题。

所以第一次实验：

**越简单越好。**

## 第一次完整实验 {#first-hardware}

现在开始正式实验。

### 第 1 步：找到实验代码

打开：

```text
App/Src/experiment.c
```

找到：

```c
static unsigned int blink_period_ms = 500U;
```

---

### 第 2 步：修改数字

把：

```c
500U
```

修改为：

```c
1000U
```

暂时不要修改其他代码。

---

### 第 3 步：Candidate Build

运行：

**Candidate Build**

它的任务是：

> 检查你刚才修改的实验代码有没有明显的编译问题。

如果通过，就继续下一步。

如果失败，也不要紧。

先看错误提示。

---

### 第 4 步：查看 Diff

检查 Studio 显示的修改。

你主要应该看到：

```text
500U → 1000U
```

确认没有误改其他内容。

然后应用修改。

---

### 第 5 步：Firmware Build

运行：

**Firmware Build**

这一步会生成真正准备给 CH32V203 使用的完整程序。

如果 Build 成功，说明：

> 完整的单片机程序已经准备好了。

但它现在仍然在电脑里。

---

### 第 6 步：连接开发板

确认：

* 开发板已经正确连接；
* WCH-Link 已连接；
* 开发板供电正常。

---

### 第 7 步：Flash

执行：

**Flash**

把刚才生成的程序写入 CH32V203。

如果 Flash 成功，说明：

> 新程序已经进入单片机。

---

### 第 8 步：观察 LED

观察开发板上的 LED。

如果程序正常运行，你应该看到：

> LED 大约每隔 1 秒改变一次亮灭状态。

也就是类似：

```text
亮
↓
等待约 1 秒
↓
灭
↓
等待约 1 秒
↓
亮
```

如果你真的看到了这个现象：

恭喜你。

你已经完成了自己的第一个单片机实验。

## 如果出现错误怎么办 {#simple-debugging}

第一次实验出现错误很正常。

不要看到报错就慌，也不要同时修改很多地方。

先判断问题出现在哪一步。

### Candidate Build 没通过

先检查：

> 我刚才修改的代码是不是写错了？

例如有没有误删其他字符。

---

### Firmware Build 没通过

说明完整程序还没有成功生成。

先查看 Studio 给出的错误提示。

此时不要急着烧录。

---

### Flash 失败

说明程序可能已经生成成功，但是还没有成功写进开发板。

可以检查：

* 开发板有没有连接；
* WCH-Link 有没有连接；
* USB 是否正常；
* 开发板有没有供电。

---

### Flash 成功，但 LED 没有正常闪烁

这说明：

> 程序已经写进单片机，但实际运行结果还需要继续检查。

不要马上随机修改代码。

可以先确认：

* 修改的数字是不是自己想要的值；
* 是否烧录的是刚刚构建的程序；
* 开发板是否正常运行。

以后我们学到更多知识之后，会逐渐掌握更系统的调试方法。

## 这一课真正学会了什么 {#what-you-learned}

回顾一下。

今天我们首先认识了：

### 什么是单片机

它可以暂时理解成：

> 一颗可以运行程序、控制电子设备的小型计算机芯片。

### 什么是开发板

开发板上除了单片机，还有：

* LED；
* 按键；
* 接口；
* 其他电子元件。

### 什么是程序

程序告诉单片机：

> 应该按照什么顺序做事情。

### 什么是编译

把我们写的 C 程序转换成单片机能够执行的程序。

### 什么是烧录

把电脑中的程序写进单片机。

### 为什么还要观察硬件

因为我们最终关心的不是电脑显示：

```text
Build succeeded
```

而是：

> 单片机有没有真的按照我们的程序控制硬件。

## 记住这一条基本流程 {#basic-workflow}

第一课最重要的不是记住某一行代码。

而是记住下面这条流程：

```text
修改代码
   ↓
检查代码
   ↓
确认修改
   ↓
生成程序
   ↓
烧录单片机
   ↓
观察硬件
```

在 Studio 中，就是：

```text
Edit
 ↓
Candidate Build
 ↓
Diff
 ↓
Firmware Build
 ↓
Flash
 ↓
Observe
```

以后几乎每一次单片机实验都会重复类似的过程。

## 想一想 {#reflection}

最后思考一个问题：

假设你已经看到：

```text
Candidate Build 成功
```

能不能说明 LED 一定会闪？

不能。

假设：

```text
Firmware Build 成功
```

能不能说明程序已经进入开发板？

也不能。

假设：

```text
Flash 成功
```

能不能说明 LED 一定按照你的想法闪？

仍然不能完全确定。

所以我们需要一步一步完成：

```text
代码检查
↓
完整构建
↓
烧录
↓
真实观察
```

每一步都在回答不同的问题。

第一课只要能够理解这一点，就已经达到了非常重要的学习目标。

## 本课小结 {#summary}

这是我们第一次接触单片机。

你现在不需要记住复杂的芯片结构，也不需要背很多专业术语。

只需要先建立几个最基本的认识：

1. **单片机是一颗能够运行程序、控制硬件的芯片。**
2. **开发板是把单片机和各种电子器件组合起来，方便我们实验的平台。**
3. **我们使用 C 语言给 CH32V203 编写程序。**
4. **电脑中的代码需要经过编译，并烧录到单片机中才能运行。**
5. **程序是否真正成功，最终还要通过真实硬件现象来确认。**

今天我们通过修改一个简单的数字，让 LED 的闪烁速度发生了变化。

这意味着：

> 你已经第一次让自己写在电脑里的程序，真正控制了现实中的硬件。
