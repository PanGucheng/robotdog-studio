## 第一课：认识单片机，让 LED 闪起来 {#introduction}

欢迎来到单片机入门课程。

如果你之前从来没有接触过单片机，不知道 MCU、GPIO、烧录这些词是什么意思，也完全没有关系。

这一课就是从零开始。

我们暂时不学习复杂的电路，也不研究芯片内部结构，更不会要求你一开始就记住很多函数。

今天只解决三个最基本的问题：

1. **单片机是什么？**
2. **程序为什么能够控制真实的电子设备？**
3. **怎样让自己修改的第一段程序真正运行在开发板上？**

最后，我们会完成第一个真正的单片机实验：

> 修改一个数字，让开发板上的 LED 按照不同的速度闪烁。

---

## 生活中其实到处都有单片机 {#mcu-around-us}

在正式介绍“单片机”之前，先想一想我们平时使用的一些东西：

- 电饭锅为什么能按照设定的时间工作？
- 空调为什么能读取温度，并自动调节运行状态？
- 电子秤为什么能读取重量并显示出来？
- 智能台灯为什么可以响应按键？
- 无人机为什么能够读取传感器并控制电机？
- 机器人为什么能够根据环境做出动作？

这些设备虽然功能不同，但背后经常存在一个共同角色：

**负责运行程序和控制硬件的芯片。**

这种芯片中非常常见的一类，就是我们今天要认识的：

**单片机。**

---

## 什么是单片机 {#what-is-mcu}

对于第一次接触单片机的同学，可以先把它理解成：

> **一台装在一颗芯片里的小型计算机。**

普通电脑可以做很多事情：

- 浏览网页；
- 播放视频；
- 运行大型软件；
- 玩游戏；
- 处理文档。

而单片机通常没有这么强的性能，它更擅长完成一些明确、具体的控制任务。

例如：

```text
读取按键
   ↓
判断有没有按下
   ↓
控制 LED
```

或者：

```text
读取温度
   ↓
程序进行判断
   ↓
控制风扇
```

再复杂一些：

```text
读取传感器
   ↓
分析当前环境
   ↓
控制电机或舵机
   ↓
让机器人运动
```

因此，我们可以先记住一个最简单的定义：

> **单片机是一颗能够运行程序，并按照程序控制电子设备的芯片。**

---

## MCU 是什么意思 {#what-is-mcu-name}

在教材、芯片资料和开发软件中，你以后还会经常看到：

**MCU**

它来自英文：

**Microcontroller Unit**

中文通常翻译为：

**微控制器。**

在我们这套入门课程中，可以暂时认为：

```text
单片机 ≈ 微控制器 ≈ MCU
```

以后看到：

- MCU 开发；
- MCU 程序；
- MCU 工程；

不用紧张。

这些都和“给单片机编写程序”有关。

---

## 单片机为什么适合控制电子设备 {#why-mcu}

既然电脑也能运行程序，为什么机器人和电器里面不用一台完整电脑，而要使用单片机？

因为很多电子设备只需要完成比较明确的任务。

例如一个智能台灯可能只需要：

```text
读取按键
+
控制灯光
```

一个电子温度计可能只需要：

```text
读取温度
+
显示结果
```

如果只是完成这些任务，就没有必要使用一整台电脑。

单片机通常具有几个很适合电子控制的特点：

- 体积很小；
- 功耗较低；
- 可以直接连接各种电子器件；
- 上电后就可以按照程序工作；
- 很适合长期、重复地执行控制任务。

因此，在：

- 家电；
- 仪器；
- 机器人；
- 无人机；
- 智能硬件；
- 自动控制设备；

中，都可以看到单片机的身影。

## 单片机怎样和现实世界联系起来 {#input-output}

单片机自己只是一颗芯片。

真正有意思的是：

> 它可以连接很多外部设备。

我们可以先把这些设备简单分成两类。

### 第一类：告诉单片机发生了什么

例如：

- 按键；
- 温度传感器；
- 光线传感器；
- CCD；
- 距离传感器。

它们把外界的信息交给单片机。

可以理解为：

**输入。**

例如：

```text
按键
  ↓
单片机
```

表示：

> 单片机可以知道按键有没有被按下。

---

### 第二类：让单片机去控制某个东西

例如：

- LED；
- 蜂鸣器；
- 显示屏；
- 电机；
- 舵机。

可以理解为：

**输出。**

例如：

```text
单片机
  ↓
LED
```

表示：

> 单片机可以控制 LED 的状态。

所以一个非常常见的单片机系统可以概括成：

```text
外界信息
   ↓
传感器 / 按键
   ↓
单片机
   ↓
程序判断
   ↓
LED / 舵机 / 电机
```

现在不需要正式学习“输入”和“输出”的电路原理。

先理解这种关系即可。

---

## 为什么我们要从 LED 开始 {#why-led}

单片机能控制很多东西。

那为什么第一课不直接控制机器马运动，而是从一颗小小的 LED 开始？

因为 LED 有一个很大的优点：

> **它的状态可以直接用眼睛看到。**

程序让 LED 亮，我们马上能看到。

程序让 LED 灭，我们也马上能看到。

如果让 LED：

```text
亮
↓
灭
↓
亮
↓
灭
```

不断重复，我们就会看到：

**LED 闪烁。**

因此 LED 非常适合作为第一个单片机实验。

它可以最直观地告诉我们：

> **程序真的在运行。**

等我们熟悉这些基础内容以后，再逐渐控制：

- 按键；
- 蜂鸣器；
- 舵机；
- 传感器；

最终组合成真正的机器马控制系统。

## 芯片和开发板不是一回事 {#chip-and-board}

第一次学习单片机时，还有一个特别容易混淆的问题：

> 单片机就是我们手里的整块电路板吗？

不是。

我们手里的整块电路板叫：

**开发板。**

而开发板上负责运行主要程序的那颗芯片，才是：

**单片机。**

可以简单理解成：

```text
机器马教学开发板

├── CH32V203C8T6   ← 单片机
├── LED
├── 按键
├── 蜂鸣器
├── 各种接口
└── 其他电子元件
```

开发板把单片机、电源、电路和各种接口组合在一起。

这样我们学习的时候，就不需要自己从零焊接所有电路。

所以：

> **单片机是一颗芯片，开发板是一整块方便我们学习和实验的电路板。**

这套机器马教学平台使用的核心单片机是：

**CH32V203C8T6**


这些功能不会在第一课全部学习。

## 机器马和单片机是什么关系 {#mcu-and-horse}

我们的最终目标不是只做一块会闪灯的开发板。

这套课程最终要控制的是：

**机器马。**

机器马真正运行起来时，大致会形成这样的过程：

```text
传感器获得信息
       ↓
CH32V203 读取信息
       ↓
程序进行判断
       ↓
CH32V203 发出控制信号
       ↓
舵机产生动作
       ↓
机器马运动
```

因此，今天看到的 LED 虽然很简单，但它已经包含了最基本的思想：

```text
程序
 ↓
单片机
 ↓
硬件
```

以后只是把：

```text
LED
```

逐渐换成：

```text
按键
传感器
舵机
机器马
```

整个系统会越来越完整。

## 什么是程序 {#what-is-program}

既然单片机可以控制硬件，那么：

> 它怎么知道什么时候应该亮灯、什么时候应该灭灯？

答案是：

**程序。**

程序就是我们提前写好的一系列指令。

例如，我们希望 LED 闪烁，可以把任务写成人能够理解的步骤：

```text
先准备好 LED

等待一段时间

改变 LED 的状态

再等待一段时间

再次改变 LED 的状态

不断重复
```

如果 LED 原来是灭的：

```text
改变一次状态
```

之后可能变成亮。

再改变一次：

```text
亮 → 灭
```

继续重复：

```text
灭 → 亮 → 灭 → 亮 → 灭……
```

于是我们就看到了 LED 闪烁。

所以 LED 并不是自己在闪。

真正控制它的是：

> **运行在 CH32V203 中的程序。**

## 我们用什么语言写程序 {#c-language}

单片机程序可以使用不同的编程语言。

这套课程主要使用：

**C 语言。**

如果你以前学习过一点 C 语言，会更容易理解后面的代码。

如果还不熟，也没有关系。

我们不会一开始就把整本 C 语言全部学完。

而是采用：

> **用到什么，再学习什么。**

例如第一课会看到：

```c
static unsigned int blink_period_ms = 500U;
```

第一次看到这一行时，不需要马上弄清：

- `static` 是什么；
- `unsigned` 是什么；
- `int` 是什么。

现在只需要知道：

> **这里保存了一个数字 500。**

等后面的课程真正需要变量、判断、函数时，我们再逐渐学习相关 C 语言知识。

## 程序开始时先做准备 {#program-init}

先看：

```c
void RHS_Experiment_Init(void)
{
    RHS_Teaching_InitLed();
}
```

现在不用研究：

```text
void
()
{}
```

分别是什么。

我们只理解里面真正做的事情：

```c
RHS_Teaching_InitLed();
```

可以暂时把它翻译成人话：

> **把 LED 准备好，让后面的程序可以控制它。**

单片机使用很多硬件之前，都需要先做一些准备。

这种准备通常叫：

**初始化。**

所以现在先形成一个很简单的认识：

```text
初始化
≈
在正式使用一个硬件之前先把它准备好
```

为什么 LED 需要初始化、内部到底做了什么，会在下一课正式学习。

## 程序为什么会一直运行 {#program-loop}

再看：

```c
void RHS_Experiment_Loop(void)
{
    RHS_Teaching_DelayMs(blink_period_ms);
    RHS_Teaching_ToggleLed();
}
```

这一部分会不断重复执行。

可以翻译成：

```text
等待一段时间
      ↓
改变 LED 状态
      ↓
再等待一段时间
      ↓
再次改变 LED 状态
      ↓
继续重复……
```

因此我们最终看到：

```text
亮 → 灭 → 亮 → 灭 → 亮……
```

单片机程序和我们平时使用的一些电脑程序有一点不同：

> 很多单片机程序上电以后，会一直运行下去。

因为电子设备通常需要一直工作。

例如机器马运行时，不可能：

```text
读取一次传感器
然后程序结束
```

而应该不断：

```text
读取
↓
判断
↓
控制
↓
再读取
↓
再判断
↓
再控制
```

这种“不断运行”的特点，以后会经常看到。

---

## 认识第一个可以修改的数字 {#blink-time}

现在看这一行：

```c
static unsigned int blink_period_ms = 500U;
```

这一课真正需要修改的，就是：

```text
500U
```

这里的数字和等待时间有关。

后面的程序中：

```c
RHS_Teaching_DelayMs(blink_period_ms);
```

会等待相应的时间。

这里使用的单位是：

**毫秒，ms。**

我们平时更熟悉的是秒。

它们之间：

```text
1000 ms = 1 s
```

所以：

```text
500 ms = 0.5 s
1000 ms = 1 s
100 ms = 0.1 s
```

如果数字变大：

> LED 每次改变状态前等待的时间更长。

如果数字变小：

> LED 改变状态会更快。

---

## 先猜一猜会发生什么 {#predict}

在真正修改程序之前，可以先做一个预测。

现在：

```c
blink_period_ms = 500U;
```

如果改成：

```c
blink_period_ms = 1000U;
```

你觉得 LED 会：

- 闪得更快；
- 还是闪得更慢？

因为等待时间从：

```text
500 ms
```

增加到了：

```text
1000 ms
```

所以 LED 应该：

> **闪得更慢。**

如果改成：

```c
blink_period_ms = 100U;
```

等待时间变短，因此：

> **LED 会闪得更快。**

先预测，再实验，是一个非常好的学习习惯。

现在开始第一次修改。

找到：

```c

```

把：

```text

```

修改成：

```text

```

最终变成：

```c

```

这一课先不要修改其他地方。

我们希望第一次实验尽可能简单。

这样最后看到 LED 变化时，可以很明确地知道：

> **变化就是由刚才这个数字引起的。**

## 为什么第一课只改一个数字 {#why-one-change}

可能有同学会觉得：

> “只改一个数字是不是太简单了？”

其实第一课故意这样设计。

因为第一次学习单片机时，比“写出复杂程序”更重要的是先体验完整过程：

```text
我修改了程序
      ↓
程序被写进单片机
      ↓
现实中的硬件真的发生变化
```

如果第一课一下修改很多代码：

- LED 配置；
- 引脚；
- 函数；
- 延时；
- 电路；

那么一旦实验失败，就很难知道问题出在哪里。

所以工程实验中有一个很实用的习惯：

> **一次只改变少量内容，然后观察结果。**

以后程序越来越复杂，这个习惯会越来越重要。

## 什么是编译 {#compile}

我们刚才修改的是 C 语言程序。

但是 CH32V203 并不能直接读懂我们看到的 C 语言文字。

例如：

```c
RHS_Teaching_ToggleLed();
```

是方便人阅读的写法。

所以，在程序真正进入单片机之前，需要先经过：

**编译。**

第一课不需要研究编译器内部原理。

可以把编译简单理解成：

> **把我们编写的 C 程序，转换成单片机能够运行的程序。**

也就是：

```text
我们能阅读的 C 程序
          ↓
        编译
          ↓
单片机能够运行的程序
```

在实验过程中，按照 Studio 中的任务提示完成程序检查和编译即可。

如果程序写错了，软件会给出错误提示。

根据提示修正程序以后，再重新编译。

---

## 编译成功以后程序在哪里 {#after-compile}

编译成功以后，有一个很容易误解的问题：

> 程序已经在 CH32V203 中运行了吗？

还没有。

编译是在：

**电脑上**

完成的。

这时新的程序仍然保存在电脑中。

而真正要运行程序的是：

**开发板上的 CH32V203。**

因此还需要把程序从电脑写进开发板。

---

## 什么是“写入开发板” {#flash-board}

Studio 中会有：

**写入开发板**

这个操作。

它的作用就是：

> 把刚刚准备好的程序写入 CH32V203。

整个过程可以简单理解成：

```text
电脑中的程序
      ↓
    WCH-Link
      ↓
CH32V203
```

WCH-Link 是电脑和开发板之间使用的一个工具。

现阶段不需要研究它内部怎样工作。

只需要知道：

> **没有把新程序写进开发板，CH32V203 就不会运行你刚刚修改的新程序。**

在其他教材中，你以后还可能看到：

- 烧录；
- 下载程序；
- Flash；

这些说法。

它们在这种场景下表达的是相近的事情。

不过在我们的课程中，优先使用软件界面里的：

> **写入开发板**

这个说法。

---

## 第一次看到程序控制真实硬件 {#first-observation}

把程序成功写入开发板以后，观察 LED。

如果你把：

```c
500U
```

改成：

```c
1000U
```

LED 应该以比较缓慢、清晰的节奏改变状态。

大致可以想象成：

```text
亮
↓
等待约 1 秒
↓
灭
↓
等待约 1 秒
↓
亮
↓
……
```

注意：

1000 ms 表示的是：

> **两次 LED 状态改变之间等待大约 1 秒。**

所以：

```text
亮 → 灭
```

大约等待 1 秒，

而：

```text
灭 → 再次亮
```

还需要再等待大约 1 秒。

## 再试一次：让 LED 变快 {#second-try}

如果前面的实验正常，可以再做一个非常简单的比较。

把：

```c
1000U
```

修改成：

```c
100U
```

然后重新按照实验任务完成：

```text
修改程序
↓
编译
↓
写入开发板
↓
观察 LED
```

这一次 LED 应该明显变快。

于是你可以得到一个非常直接的结论：

```text
1000U
↓
等待较长
↓
LED 较慢

100U
↓
等待较短
↓
LED 较快
```

这说明：

> **电脑中修改的数字，最终真的改变了开发板上 LED 的行为。**

这就是你的第一个“软件控制硬件”的实验。

## 如果程序出现错误怎么办 {#simple-errors}

第一次修改代码时，出现错误非常正常。

例如原本：

```c
static unsigned int blink_period_ms = 1000U;
```

如果不小心删除了一些符号，软件可能会提示程序无法通过检查或编译。

这时不要紧张。

也不要一次修改很多地方。

最简单的做法是：

1. 看软件提示错误出现在哪个文件；
2. 看提示的大致位置；
3. 检查自己刚才改过的地方；
4. 修正以后重新尝试。

第一课只要求修改一个数字，因此如果出现问题，优先检查：

```c
blink_period_ms = ...
```

这一行即可。

## 如果写入成功但 LED 没闪怎么办 {#no-led}

还有一种情况：

程序已经成功写入开发板，但是 LED 没有出现预期变化。

这时也不要随便乱改程序。

可以先做几个最简单的确认：

- 开发板是否正常供电；
- WCH-Link 是否连接正常；
- 是否刚刚重新完成了编译；
- 是否把最新程序写入了开发板；
- 修改的数字是不是自己预期的值。

如果这些都没有问题，再进一步检查。

以后课程继续深入以后，我们会逐渐学习更加系统的程序调试方法。

第一课只需要建立一个习惯：

> **出现问题时，一项一项检查，而不是一次乱改很多东西。**

## 单片机程序和普通电脑程序有一点不同 {#program-runs-on-chip}

现在再回头看整个过程：

```text
电脑上修改 C 程序
        ↓
编译
        ↓
写入开发板
        ↓
CH32V203 开始执行
        ↓
LED 发生变化
```

这里有一个非常重要的特点：

> **我们写代码的电脑和最终运行代码的设备，不是同一个东西。**

你是在电脑上：

- 写代码；
- 修改代码；
- 编译程序。

但是最后真正执行程序的是：

**CH32V203。**

这也是单片机开发和普通电脑编程一个非常直观的区别。

单片机和开发板是同一个东西吗？

为什么在电脑里把：

```text
500U
```

```text
1000U
```

还需要经过：

```text
编译
↓
写入开发板
```

在本课中，就是观察 LED 是否按照预期闪烁。

## 本课小结 {#summary}

这是我们正式学习单片机的第一课。

现在不需要记住大量专业术语。

只需要真正理解下面几件事情。

### 1. 单片机是什么

单片机可以简单理解成：

> **一颗能够运行程序，并控制电子设备的芯片。**

---

### 2. 我们使用什么单片机

这套机器马教学平台使用：

**CH32V203C8T6。**

它是开发板上的核心控制芯片。

---

### 3. 单片机能做什么

它既可以接收外界信息：

```text
按键
传感器
CCD
```

也可以控制：

```text
LED
蜂鸣器
舵机
```

---

### 4. 程序怎样进入单片机

最基本的过程是：

```text
编写和修改程序
        ↓
       编译
        ↓
    写入开发板
        ↓
 CH32V203 运行程序
```

---

### 5. 今天完成了什么

我们修改了：

```c
blink_period_ms
```

的数值。

然后把新的程序写入开发板。

最终观察到：

> **LED 的闪烁速度按照我们的修改发生了变化。**

也就是说：

> **你已经第一次使用自己修改的程序控制了真实硬件。**

下一课，我们将继续研究今天已经使用过的 LED。

今天我们只知道：

> “程序能够控制 LED。”

下一课要正式回答：

> **CH32V203 到底是怎样控制这颗 LED 的？**

这会带我们认识单片机最基础、也是以后使用频率最高的功能之一：

**GPIO。**
