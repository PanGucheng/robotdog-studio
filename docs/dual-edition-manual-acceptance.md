# RobotDog Studio 双发行版人工验收清单

更新日期：2026-08-06

本清单只包含必须由人工操作或观察的项目。执行前保留现有 `%APPDATA%\robotdog-studio`，不要手工移动或删除历史数据；测试结果至少保存安装器文件名、应用“关于/标题”截图、关键页面截图和失败日志。

## 1. 安装与共存

1. 在干净的 Windows 10/11 x64 电脑上分别运行趣味巡线版和单片机入门版 NSIS 测试安装器。
2. 确认安装器显示不同产品名，安装后开始菜单、安装目录、可执行文件和卸载项能够区分两个版本。
3. 同时启动两个版本，确认窗口标题和顶部版本标签正确，互不顶替进程和数据。
4. 分别卸载其中一个版本，确认另一版本仍能启动且项目数据不受影响。

预期：两个版本可共存；趣味版身份为 `RobotDog Studio 趣味巡线版`，单片机版身份为 `RobotDog Studio 单片机入门版`。

## 2. 历史数据迁移与隔离

1. 在已有旧版数据的电脑上首次启动趣味巡线版，记录迁移前旧项目数量。
2. 确认旧项目、Git 历史、AI 对话、活动候选和已有固件产物仍可访问；抽查至少一个旧项目的代码与最近一次存档。
3. 再启动单片机入门版，确认其中没有出现任何旧巡线项目或趣味版 AI 密钥。
4. 在两版各新建一个项目并重启应用，确认项目列表只显示本版项目。

预期：旧目录原样保留；只向趣味版复制一次；两个新数据目录此后独立变化。若迁移失败，停止测试并备份 `%APPDATA%\robotdog-studio` 与 `%APPDATA%\RobotDogStudio-Fun` 后提交日志，不要反复重装。

## 3. 趣味巡线版回归

1. 新建项目，确认没有版本选择器，默认内容仍包含巡线参数、CCD 和学生控制代码。
2. 手动修改一个允许文件，执行候选检查、查看 Diff、确认保存、撤销，观察 Git 存档编号变化。
3. 让 AI 只调整一个巡线参数，确认表达适合中小学生，且修改必须先经过 Diff 和人工确认。
4. 完成程序生成；在模拟设备中检查连接、急停、下载和教师恢复入口。

预期：原有教学闭环没有因双版本改造退化，AI 不能修改受保护文件或自动烧录。

## 4. 单片机入门版闭环

1. 新建项目，确认默认名称为“单片机练习”，工作台包含工程代码、编译与问题、修改确认、烧录与运行、程序资源和设置。
2. 检查 `App/Src/experiment.c` 与 `App/Inc/experiment.h` 可编辑，`Core/Src/student_control.c` 与 `Core/Inc/student_control.h` 明确只读。
3. 在 `App/Src` 或 `App/Inc` 创建一个子目录文件，确认文件可见；尝试修改 `Core`、启动文件或链接脚本，确认被拒绝。
4. 制造一次 C 语法错误，确认编译页能定位问题；修复后确认候选预检通过、Diff 可审查、保存后完整固件可生成。
5. 询问 AI 一个 C 语言或编译问题，确认其使用大学入门层级术语并要求用编译或硬件现象验证，且不会声称模板已提供未验证外设课程。

## 5. 驱动、烧录与真实硬件

1. 在设备管理器中记录安装前状态，安装任一 NSIS 包后确认 WCH-Link 驱动已安装且应用仍以普通权限运行。
2. 连接目标 CH32V203 开发板，依次执行探测、编译、烧录和复位；保存完整编译与 OpenOCD/WCH-Link 日志。
3. 分别烧录两版创建的最小项目，观察启动、串口或机器马安全状态；验证急停和物理断电手段。
4. 拔线、接错设备或中途取消各测试一次，确认没有自动重试写入错误设备，且失败信息可用于恢复。

预期：任何真实烧录都需要明确人工动作；启动、链接、Flash、Bootloader 与下载算法不能被学生或 AI 修改。

## 6. 结果记录

每项记录 `通过/失败/未测`、Windows 版本、安装包 SHA-256、硬件版本、固件基线、操作时间和截图/日志路径。发现失败时保留两个发行版的数据目录和当次安装包，不清理现场；将最短复现步骤与日志一并反馈。
