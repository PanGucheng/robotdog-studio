# RobotDog Studio 单片机入门版代码优先工作台改造计划

更新日期：2026-08-07

状态：产品方案已确认，等待按阶段实施

适用发行版：`mcu-foundations`

关联文档：[课程框架详细实施计划](./mcu-course-framework-implementation-plan.md) · [课程框架架构说明](./mcu-course-framework-architecture.md)

## 1. 产品结论

单片机入门版调整为“代码始终是学习工作台主体”的桌面布局。学生进入课次工程后，左侧代码主区持续显示真实工程目录和代码，右侧只保留“课程”“构建与运行”“AI 助教”三个工具。修改确认成为代码主区的 Diff 状态，烧录和资源并入构建流程，设置移入全局菜单。

本轮方案同时落实此前确定的调整：

1. 大学生版展示参与实际固件构建的完整工程目录，不再只展示按“源文件、头文件、只读接口”平铺的少量文件；
2. 文件树合并显示学生课次覆盖层和受保护固件基线，并明确标记来源、工程角色和修改权限；
3. `App` 教学代码可在安全草稿中修改，主固件、启动代码、链接脚本、厂商外设库和构建配置默认只读；
4. 工程树、编辑器和当前文件上下文在工具切换时保持存在，右侧工具从七项收敛为课程、构建与运行、AI 助教三项；
5. 趣味巡线版继续使用现有面向中小学生的工作台，不复制一套实现，也不被迫采用大学生版的信息密度。

这里的“完整工程”指**对理解和构建固件有意义的工程视图**，不是把 Git、缓存、临时目录和应用内部数据原样暴露给学生。

## 2. 已核实的现状与问题

### 2.1 当前布局

当前 `App.tsx` 的主区域是两列：

```text
AI 对话面板                         工作台
约 38%                              约 62%
                                   └─ 顶部标签切换课程、任务、代码、
                                      编译、修改、烧录、资源、设置
```

这会产生三个问题：

- AI 对话长期占据左侧大块空间，但代码只在“工程代码”标签中临时出现；
- 查看课程步骤、编译错误或 AI 解释时，学生需要离开代码页面，难以对照理解；
- “课程、代码、构建、烧录”被表现成并列页面，不能体现代码是大学生单片机学习的核心对象。

### 2.2 当前工程文件模型

当前 `StudentCodeEditor` 只读取 `StudentCodeFile[]`：

- 递归列出工作区的 `App/Src` 和 `App/Inc`；
- 固定追加 `Core/Inc/student_control.h` 和 `Core/Src/student_control.c`；
- Renderer 一次获取文件描述和完整文本，再按教学分组平铺显示。

课次工作区实际上是教学覆盖层。完整固件构建时，系统还会使用工作区绑定的 CH32V203 固件基线。因此只修改文件栏样式，无法形成真实完整的工程目录，也会掩盖“课次代码覆盖主固件”的关系。

### 2.3 当前构建与验证信息过载

当前 MCU 工作台把“编译与问题、修改确认、烧录与运行、程序资源、设置”作为五个并列页面。构建页还同时展示：

- 工具链就绪徽标和 GCC、Objcopy、OpenOCD 组件详情；
- 连接/更新、教师恢复、构建进度和输出目录；
- ELF、HEX、BIN、MAP 四类产物卡；
- text、data、bss、total 四项数值；
- 工作区提交、输入哈希、产物身份和完整编译日志。

其中资源数值又在“程序资源”页重复展示，烧录状态则被拆到另一页。技术信息本身有价值，但默认同时出现会掩盖学生当前真正要做的动作，也让“修改 → 确认 → 编译 → 烧录”被页面边界割裂。

## 3. 设计目标与非目标

### 3.1 设计目标

- 学生进入课次工程后，不论查看课程、编译、AI 或烧录，代码主区都保持可见；
- 学生能够在真实目录关系中认识应用代码、适配层、主程序、芯片外设库、启动、链接和构建配置；
- 从编译错误、课程步骤和 AI 解释可以直接定位文件、行号和选区；
- 文件来源和修改权限一眼可辨，不能把只读基线误认为自己的课次文件；
- 完整工程视图与实际构建所用工作区提交和固件基线一致；
- 正常流程每个时刻只突出一个主要动作和当前需要处理的问题；
- 构建、修改确认、烧录和资源共用一个按状态逐步展开的流程，不重复展示同一数据；
- 大窗口充分利用横向空间，小窗口或高缩放下仍保证编辑器可用；
- Main、Preload 和 Renderer 继续使用稳定、受控接口，不因展示完整目录而扩大文件访问权限。

### 3.2 非目标

- 不把 RobotDog Studio 做成通用 VS Code 替代品；
- 不开放任意文件夹、终端、Shell、插件或自由构建任务；
- 不允许学生修改启动文件、链接脚本、厂商库、烧录配置或主固件基线；
- 不把完整固件复制到每个课次工作区，只为显示目录制造重复文件；
- 不在本轮实现源码搜索、重构、调试器、Git 图形客户端和多窗口编辑；
- 不改变 AI 候选区、编译预检、Diff 确认和人工烧录确认的安全闭环。

## 4. 设计方向

### 4.1 主题、受众和页面任务

- 主题：CH32V203 RobotDog 嵌入式固件实验台；
- 受众：正在学习 C 语言、单片机工程结构和编译烧录流程的电子类大学生；
- 单一任务：让学生在真实工程上下文中持续阅读和修改代码，同时就近获得课程、构建和 AI 辅助。

### 4.2 视觉语言

沿用现有 RobotDog Studio 的仪器工作台语言，不照搬 VS Code 配色：

| 角色 | 建议色值 | 用途 |
| --- | --- | --- |
| 深海军蓝 `#10243A` | 品牌与结构 | 顶栏、重要状态、编辑器外框 |
| 代码蓝黑 `#10283A` | 代码画布 | Monaco 编辑器背景 |
| 传感青 `#00A8C6` | 当前信号 | 选中节点、活动工具、定位关系 |
| 构建琥珀 `#F3A712` | 待处理状态 | 编译中、警告、未验证 |
| 验证绿 `#16A36A` | 已通过状态 | 构建成功、保存完成、连接就绪 |
| 故障红 `#D92D20` | 阻断状态 | 编译失败、烧录失败、危险动作 |

字体继续使用现有、可离线分发的组合：

- 标题与结构：`Bahnschrift` + `Microsoft YaHei UI`；
- 正文与控件：`Microsoft YaHei UI` + `Noto Sans SC`；
- 代码、路径、版本和数值：`Cascadia Mono` + `Consolas`。

本工作台的识别性元素是右侧“仪器工具坞”：一条克制的竖向工具轨只显示课程、构建与运行、AI 三项及其状态点。构建与运行内部使用一条真实流程轨表示“修改 → 编译 → 烧录”，而不是为每一步增加一个页面。它来自单片机实验台的信号和状态仪表，不是装饰性的通用侧栏。

## 5. 新信息架构

### 5.1 有课次工程时的标准布局

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 顶栏：RobotDog Studio / 项目 / 基线 / 连接 / 教师模式 / 急停                 │
├──────────────────────────────────────────────────────────────────────────────┤
│ 项目上下文：课程 › 课次 › 第 N 次练习       草稿状态 / 存档 / 基线版本       │
├──────────────┬──────────────────────────────────────┬─────┬──────────────────┤
│ 工程目录     │ 代码主编辑区                         │工具 │ 右侧辅助面板     │
│ 220–300 px   │ min 560 px                           │轨   │ 340–460 px       │
│              │                                      │     │                  │
│ RobotDog     │ App/Src/experiment.c                 │课程 │ 当前任务/进度    │
│ Firmware     │ ┌──────────────────────────────────┐ │运行 │ 修改/编译/烧录   │
│ ├─ App       │ │ Monaco 编辑器或代码 Diff        │ │     │ 当前一步与问题   │
│ ├─ Core      │ │                                  │ │ AI  │ 对话/解释/修复   │
│ ├─ User      │ │                                  │ │     │                  │
│ ├─ Peripheral│ └──────────────────────────────────┘ │     │                  │
│ ├─ Startup   │ 状态栏：行列 / C / 只读 / 基线来源   │     │                  │
│ └─ Ld        │                                      │     │                  │
└──────────────┴──────────────────────────────────────┴─────┴──────────────────┘
```

“左侧代码主区”由工程目录和编辑器共同组成，占据主要宽度。右侧工具切换只改变辅助面板，不卸载工程树和编辑器。

### 5.2 无项目与课程浏览

没有活动工作区时不存在可显示的代码，课程中心可以占用主画布：

```text
课程中心 → 选择课次 → 创建/继续练习 → 进入代码优先工作台
```

进入工程后：

- “课程”工具显示当前课次任务、问题和完成条件；
- “浏览全部课程”是显式离开工程上下文的操作，返回时恢复原文件、光标和右侧工具；
- 普通 `mcu-sandbox` 没有课次任务时，课程工具显示“这是自由练习项目”，代码和其他工具仍可使用。

### 5.3 主编辑区模式

主编辑区保持代码语义，但允许在明确动作下切换模式：

| 模式 | 触发方式 | 主区内容 | 右侧内容 |
| --- | --- | --- | --- |
| 阅读/编写 | 选择文件、开始编写 | Monaco 文件编辑器 | 当前工具面板 |
| 修改确认 | 候选预检通过 | Monaco Diff Editor | “构建与运行”显示摘要、应用/放弃 |
| 编译定位 | 点击错误 | 对应文件和行号 | 结构化错误、AI 解释入口 |
| 构建输出 | 点击“展开日志” | 编辑器下方可收起输出区 | 构建状态和主要动作 |

Diff 仍然属于代码主区，不再作为与代码无关的独立整页。烧录、课程和 AI 不替换主编辑器。

## 6. 完整工程目录方案

### 6.1 虚拟合并树

界面显示一个与实际构建结果一致的虚拟根：

```text
RobotDog Firmware · <baseline short commit>
├─ App/                           课次覆盖层 · 可编辑
│  ├─ Inc/
│  └─ Src/
├─ Core/
│  ├─ Inc/student_control.h       课程适配 · 只读
│  ├─ Src/student_control.c       课程适配 · 只读
│  └─ ...                         芯片核心支持 · 只读
├─ User/                          主固件功能 · 只读
├─ Peripheral/
│  ├─ inc/                        厂商外设声明 · 只读
│  └─ src/                        厂商外设实现 · 只读
├─ Startup/                       启动代码 · 只读
├─ Ld/Link.ld                     链接脚本 · 只读
├─ Debug/                         调试配置 · 只读
├─ cmake/                         构建模块 · 只读
├─ student-config/                教学配置 · 按策略标记
├─ CMakeLists.txt                 构建入口 · 只读
├─ CMakePresets.json              构建预设 · 只读
├─ robotdog.firmware.json         固件描述 · 只读
└─ README.md                      工程说明 · 只读
```

合并规则：

1. 工作区/候选区中的教学覆盖文件优先于固件基线的同路径文件；
2. 其余节点来自工作区绑定的固件基线，而不是 Renderer 提供的任意目录；
3. 同一路径在界面只显示一次，但节点保留真实来源；
4. 工作区基线 ID 或 commit 与当前可用基线不一致时，树显示阻断提示，不能静默混用新基线；
5. 浏览基线文件不会把它复制进学生 Git，也不会加入 AI 可编辑上下文。

### 6.2 默认隐藏内容

默认不显示：

- `.git`、`.github`、`.vscode`、`.eide`、`.mrs`；
- `node_modules`、构建输出、缓存和临时 staging；
- AI 候选目录、课程进度、受管数据目录和应用日志；
- ELF、HEX、BIN、MAP 等产物不进入工程树；默认只显示“程序文件已生成”，具体文件放入“构建与运行”的技术详情；
- 与首期教学无关的维护脚本和内部测试夹具。

可在后续加入“显示工程辅助文件”开关，用于显示 `docs`、`tests`、`tools` 等内容，但首期不作为必要范围。

### 6.3 节点信息

每个文件节点至少包含：

```ts
type ProjectExplorerNode = {
  id: string                    // Main 生成的稳定/不透明 ID
  parentId?: string
  name: string
  kind: 'directory' | 'file'
  language?: 'c' | 'cpp' | 'asm' | 'linker' | 'cmake' | 'json' | 'yaml' | 'markdown' | 'text'
  origin: 'lesson-overlay' | 'firmware-baseline'
  role: 'student-code' | 'course-adapter' | 'application' | 'core' | 'peripheral' | 'startup' | 'linker' | 'build' | 'config' | 'documentation'
  access: 'editable' | 'read-only'
  state?: 'normal' | 'modified' | 'error' | 'warning'
  displayPath: string
}
```

Renderer 使用 `id` 请求文件，不能把磁盘绝对路径或任意相对路径传给 Main。`displayPath` 只用于面包屑和教学说明。

### 6.4 工程讲解

选择目录或只读文件时，右侧“课程”工具可以显示：

- 该节点属于哪一层；
- 它在编译、链接和运行中的作用；
- 本课是否要求理解；
- 为什么可以或不可以修改；
- 与当前教学文件的调用关系。

课程步骤可登记可选的 `fileTarget`（稳定工程角色 + 受限工程相对路径 + 可选行号/符号），实现“定位 `main.c`”“查看 `Link.ld`”等引导。新增普通课程仍以资源配置为主，不在 React 中硬编码课名。

建议的首轮工程导览顺序：

```text
Startup → User/main.c → Core/student_control.c → App/experiment.c
        → CMakeLists.txt → Ld/Link.ld → Peripheral
```

## 7. 右侧工具坞

右侧采用“窄工具轨 + 可调整宽度的内容面板”。工具轨始终可见；内容面板允许收起，为编辑器让出空间。首期只保留三个工具，不能再按每个后端服务增加一个页面。

### 7.1 工具定义

| 工具 | 主要内容 | 与代码联动 |
| --- | --- | --- |
| 课程 | 当前课次、当前一步、简洁步骤列表、问题和完成状态 | 步骤定位文件/符号；保持编辑器不卸载 |
| 构建与运行 | 修改确认、候选预检、完整构建、必要诊断、资源摘要、设备连接与烧录 | 根据当前状态显示唯一主动作；Diff 和错误定位发生在代码主区 |
| AI 助教 | 对话、选中代码解释、诊断解释、受限修复 | 自动携带当前课次、文件和选区上下文 |

设置不再作为学习工具。顶栏齿轮打开全局设置对话框，包含缩放、工具链、固件基线和教师诊断。课程目录仍是无项目时的主画布，不占用课次工程中的第四个工具。

### 7.2 “构建与运行”状态流程

“构建与运行”不是把四个旧页面纵向堆叠，而是根据可信服务状态一次只展开当前阶段：

```text
修改草稿 → 检查修改 → 确认差异 → 生成程序 → 写入开发板 → 完成
```

| 当前状态 | 默认展示 | 唯一主动作 | 收起的次要信息 |
| --- | --- | --- | --- |
| 没有修改 | 当前代码尚未产生草稿；最近完整构建是否有效 | 生成程序（需要时） | 上次操作时间 |
| 草稿编辑中 | 修改文件数量、保存状态 | 检查修改 | 草稿内部 ID |
| 预检失败 | 最重要的 1–3 条结构化错误 | 定位第一处错误 | 完整编译输出 |
| 预检通过 | 修改摘要；主代码区显示 Diff | 应用修改 | 文件级完整 Diff 导航 |
| 已应用/产物过期 | 提示代码已变化，需要重新生成 | 生成程序 | 旧产物身份 |
| 正在构建 | 总体进度和当前阶段 | 取消 | 每个编译命令和源文件滚动信息 |
| 构建成功 | “程序已生成”、Flash/RAM 两条占用条、设备状态 | 写入开发板 | 具体产物、原始 size 数值和哈希 |
| 构建失败 | 最重要的错误和对应文件 | 定位第一处错误 | 重新生成、完整日志和命令行 |
| 烧录中 | 进度、目标设备和可取消状态 | 取消烧录 | OpenOCD 原始输出 |
| 烧录完成 | 已写入并校验、完成时间 | 再次运行（需要时） | 技术回执 |

学生仍需分别确认“应用修改”和“写入开发板”。合并页面不能合并这两个安全确认，也不能让 AI 或课程自动越过它们。

### 7.3 信息删减规则

| 现有信息 | 新的默认展示 | 技术详情/设置 | 处理结论 |
| --- | --- | --- | --- |
| GCC、Objcopy、OpenOCD 三项详情 | 正常时不显示；异常时显示“工具链不可用” | 全局设置中列出组件与路径 | 从正常学习流程移除 |
| 构建输出目录 | 不显示 | 技术详情可复制 | 默认隐藏本机路径 |
| ELF/HEX/BIN/MAP 四张产物卡 | 一行“程序文件已生成” | 可展开文件名、大小和导出入口 | 合并，不逐卡展示 |
| text/data/bss/total 四张卡 | Flash、RAM 两条占用条 | 展开后显示原始字段 | 去掉重复资源页 |
| 工作区提交、输入哈希、产物哈希 | 只显示“与当前代码一致”或“需要重新生成” | 教师技术详情 | 学生不直接读取证明字段 |
| 默认展开的完整编译日志 | 只显示结构化错误和警告 | “查看完整日志”折叠区 | 成功日志默认隐藏 |
| 教师恢复卡 | 学生模式不显示 | 教师诊断/恢复入口 | 不与正常构建并列 |
| 工具链原理和重复说明文案 | 首次出现时一条短提示 | 课程材料或帮助 | 不在每次构建重复展示 |
| 独立“程序资源”页面 | 构建成功状态内显示资源摘要 | 技术详情显示原始数据 | 删除独立入口 |
| 独立“修改确认”页面 | 代码主区 Diff + 运行工具的操作条 | 历史与撤销折叠显示 | 删除独立入口 |
| 独立“烧录与运行”页面 | 构建成功后在同一流程出现 | 驱动修复和原始日志在诊断区 | 删除独立入口 |

不得删减的内容：编译错误的可定位信息、修改前后差异、应用/放弃动作、产物是否过期、目标设备身份、真实/模拟状态区别、烧录确认、取消和失败恢复建议。

### 7.4 课程与 AI 面板精简

“课程”默认只显示：课次名称、`已完成步骤/总步骤`、当前步骤、下一步动作。完整步骤列表默认折叠；问题输入和人工观察只在对应步骤成为当前步骤时展开。移除大幅 hero、环形百分比、重复的最近操作卡和同时展开的多个完成条件面板。

“AI 助教”默认只显示对话、当前上下文标签和输入框。模型名称、Reasonix 模式、运行时路径、候选 ID 等不进入学生主界面；连接或模型异常时才显示简短、可行动的错误。AI 产生修改后，Diff 在代码主区打开，“构建与运行”负责确认动作。

MCU 顶栏中的六步流水线与新的状态流程重复，应在本版隐藏或收敛为一个状态短句。项目上下文栏只保留项目/课次、草稿状态、设备连接和必要警告；基线 commit、模拟标志等进入悬浮说明或技术详情。

### 7.5 默认打开与焦点规则

- 新建/继续课程练习：默认打开“课程”；
- 普通 MCU sandbox：默认打开“AI 助教”或上次使用工具；
- 候选编译失败：保持当前文件，同时打开“构建与运行”并聚焦第一条错误；
- 候选通过预检：打开“构建与运行”，主区显示 Diff；
- 应用修改后：“构建与运行”进入需要重新生成程序的状态；
- 用户选中代码并点击解释：打开“AI 助教”；
- 构建成功后不自动烧录；“构建与运行”显示明确的“写入开发板”按钮。

自动切换必须尊重正在输入的 AI 消息和未关闭的确认动作；相同优先级事件只更新状态徽标，不反复抢焦点。

### 7.6 面板尺寸与响应式规则

- 工程目录默认 260 px，可在 220–340 px 内拖动；
- 右侧面板默认 390 px，可在 340–520 px 内拖动；
- 工具轨约 48 px；
- 中央代码区正常状态不小于 560 px；
- 宽度不足时右侧面板改为覆盖式抽屉，工具轨仍在右侧；
- 工程目录在窄窗口仍保留左侧位置，可手动收起为约 44 px 的“工程”按钮，不移动到右侧；
- 125%–175% UI 缩放时优先让右侧面板覆盖，不把 Monaco 压缩到不可编辑宽度；
- 面板尺寸、收起状态、活动工具和最后打开文件按发行版/工作区轻量持久化。

## 8. 状态与路由重构

现有 `WorkbenchRoute` 同时承担整页导航和业务目标。改造后应拆成三个正交状态：

```ts
type McuShellMode = 'course-catalog' | 'workspace'
type EditorSurface = 'source' | 'candidate-diff'
type McuToolId = 'course' | 'run' | 'assistant'
type BuildRunPhase = 'idle' | 'draft' | 'checking' | 'review' | 'build' | 'flash' | 'complete' | 'failed'
```

要求：

- `StudentCodeEditor` 或后续 `McuCodeWorkspace` 在 `workspace` 模式下保持挂载；
- 切换 `McuToolId` 不重建 Monaco model；
- 当前文件、光标、滚动位置和未写入草稿状态不依赖右侧工具组件生命周期；
- 原 route ID 在迁移期映射到新状态：`build/review/flash/resources` 均打开 `run` 工具并定位相应阶段，`settings` 打开全局对话框；课程资源无需一次性重写；
- 趣味巡线版继续使用当前 `Workbench` 路由，不受 MCU shell 状态影响。

建议组件边界：

```text
App
├─ FunStudioShell                         现有趣味版组合
└─ McuStudioShell
   ├─ McuCourseCatalog                    无项目/显式课程浏览
   ├─ McuWorkspaceShell
      ├─ ProjectExplorer
      ├─ CodeSurface
      │  ├─ SourceEditor
      │  └─ CandidateDiffEditor
      ├─ McuToolRail
      └─ McuToolPanel
         ├─ CourseTool
         ├─ BuildRunTool
         │  ├─ CandidateReviewActions
         │  ├─ BuildDiagnostics
         │  └─ DeviceFlashActions
         └─ AssistantTool                 复用 ChatPanel 逻辑
   └─ GlobalSettingsDialog
```

共享业务组件和 hooks，不复制候选、编译、烧录或 AI 服务逻辑。

## 9. Main / IPC / Preload 方案

### 9.1 新增只读工程浏览服务

新增 `ProjectExplorerService`，只在 `mcu-foundations` 注册，职责包括：

- 根据 workspace ID 读取课程工作区身份和绑定基线；
- 枚举允许展示的工作区覆盖文件和基线节点；
- 应用合并优先级、目录白名单、扩展名和大小限制；
- 为节点生成不透明 ID，并在 Main 内解析 ID；
- 返回节点元数据，按需读取单个文件内容；
- 对候选区只映射允许修改的教学文件，不扩大现有补丁策略；
- 返回基线短提交、来源和只读原因，供界面标识。

建议 API：

```text
getProjectExplorer(workspaceId, candidateId?)
readProjectExplorerFile(workspaceId, nodeId, candidateId?)
```

目录列表与文件内容分离，避免首次打开时一次把完整 `Peripheral` 文本发送给 Renderer。

### 9.2 与现有候选服务的关系

- 保留 `listStudentCodeFiles()` 供趣味版、AI 上下文和迁移期使用；
- 手动写入仍通过 `writeManualDraft()`，Main 必须把 node ID 解析为当前候选区中已登记、可编辑的教学路径；
- 只读基线文件不能进入 `writeManualDraft()`、AI repair backup 或 patch apply；
- 浏览完整工程不会把所有基线内容注入模型，AI 只获得当前选中片段和原有受控课程上下文；
- 若以后允许 AI 解释只读基线文件，只传学生明确选择的限长片段，不传整个工程。

### 9.3 安全与失败行为

- 拒绝 Renderer 提交绝对路径、`..`、符号链接目标或未知节点 ID；
- 单文件文本建议限制在 256 KB，二进制文件不在代码浏览接口中返回；
- 基线不可用或与工作区不一致时，保留学生覆盖文件可读，但基线节点显示不可用，完整构建继续按现有规则阻断；
- 文件在读取期间变化时刷新对应节点，不重新加载整个工作台；
- 不在错误文案中向学生暴露本机绝对路径，教师诊断区可显示受控技术信息。

## 11. 测试矩阵

### 11.1 必须自动覆盖

- 工作区覆盖文件优先于同路径基线文件；
- 文件树只来自工作区身份和绑定基线，Renderer 不能指定磁盘路径；
- 隐藏目录、扩展名、大小和符号链接规则；
- 基线节点始终只读，无法通过手动草稿、AI 或伪造 IPC 写入；
- 切换课程、构建与运行和 AI 时编辑器状态保持；
- 原修改确认、烧录和资源 route 正确映射到构建与运行的对应阶段，不再产生独立页面；
- 构建与运行在各阶段只展示一个主要动作，完整技术信息默认收起；
- Flash/RAM 摘要不再在两个位置重复展示；
- 编译诊断定位正确文件和行号；
- Diff 应用/放弃/撤销继续遵守现有候选流程；
- 课程步骤文件定位只能指向允许展示的工程节点；
- MCU 与趣味版布局和资源隔离；
- 打包后离线读取基线，开发模式不依赖安装/解包验证。

### 11.2 人工复核清单

1. 使用 `start-mcu-dev.cmd` 打开单片机版并进入前两个无硬件课；
2. 展开完整工程树，确认目录层次、滚动、选中和折叠状态清楚；
3. 打开一个可编辑文件和多个只读基线文件，核对权限提示；
4. 开始安全草稿，输入未保存内容，在三个右侧工具之间切换再返回；
5. 制造编译错误，从“构建与运行”点击错误并定位到正确行；
6. 选中代码请求 AI 解释，确认代码仍可见且 AI 面板在右侧打开；
7. 生成候选修改，在主区查看 Diff，并从同一个运行工具继续完成应用、生成程序和可选烧录；
8. 核对正常构建成功状态只显示程序已生成、Flash/RAM 摘要和下一步，技术详情默认收起；
9. 调整工程树和右侧面板宽度，关闭重开后检查记忆；
10. 在 100%、125%、150%、175% 缩放和窄窗口下确认代码仍可操作；
11. 打开趣味巡线版，确认原有工作台没有被 MCU 三栏布局替换。

复核记录应包含测试提交、启动方式、窗口尺寸/缩放和失败截图。无问题的每次操作不要求单独绑定 Git commit 或产物哈希。

## 12. 完成定义

只有同时满足以下条件，代码优先工作台改造才可标记完成：

- 进入 MCU 工程后，工程树和代码主区在所有辅助工具切换中持续存在；
- 工程树展示实际构建需要理解的完整结构，并明确区分课次覆盖层与固件基线；
- 学生能够认识并定位应用代码、适配层、主程序、外设库、启动、链接和构建入口；
- 只有现有补丁策略允许的教学文件可修改，其余文件可靠只读；
- 右侧只有课程、构建与运行、AI 助教三个工具，设置不占学习工具位置；
- 修改确认在代码主区完成，烧录和资源摘要按阶段并入构建与运行，不再形成独立页面；
- 默认界面不展示工具链组件列表、本机输出路径、成组产物卡和哈希证明；需要诊断时仍可展开技术详情；
- 编译错误、课程步骤和 AI 选区能够回到准确代码上下文；
- 候选、预检、Diff、完整构建和人工烧录确认安全边界没有回退；
- 趣味版继续共享核心实现但保持自己的低复杂度界面；
- 开发模式、Electron smoke 和打包后离线运行均通过。
