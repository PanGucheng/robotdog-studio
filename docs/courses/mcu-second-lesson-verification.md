## 学生操作路径

使用 Computer Use 技能的 `sky` API，在最大化的真实 Studio 窗口内操作。开发模式使用独立工作区 `mcu-lesson2-review-20261014`，避免修改用户原有实验。

1. 从课程中心进入第二课作者验证，确认前置课提示，阅读讲义后点击末尾「开始实验」。创建独立工程，展开 `App → Src → experiment.c`，核对头文件、PB8 与任务定位入口。
2. 按任务 2、3、4 分别在编辑器填写 GPIOB 时钟、结构体参数与 `GPIO_Init`，逐次保存。保留 `Delay_Init()` 和函数骨架。
3. 打开编译面板，再点击实际「编译」。初始化代码完整编译、链接通过，生成 ELF / HEX / BIN / MAP。
4. 将 Loop 提示替换为 `GPIO_ResetBits(GPIOB, GPIO_Pin_8);`，保存后旧构建失效，重新编译通过。
5. 故意删除调用末尾分号，保存并编译。编译器报告 `experiment.c:28:38` 的 `expected ';' before '}' token`；「问题」条目可以定位第 28 行。失败代码不能使用旧固件烧录。
6. 改为 ResetBits、Delay_Ms(500)、SetBits、Delay_Ms(500)，保存、重新编译通过。软件任务完成 9 / 14；烧录、实际观察和最终反思没有代为勾选。
7. 实际使用 AI 助教询问 `&GPIO_InitStructure` 与 `GPIO_Speed_50MHz`，要求只解释、不修改代码。回答完成，解释地址传递与软件延时；没有应用代码修改。没有读取或记录 API key。

以上完整编辑流程在内容 v14 的第一份实验完成。更新至 v15 后，验证旧实验显示兼容历史练习提示，按 stepId 对齐；另从讲义创建第二份 v15 实验，确认新模板、文件树、任务定位及阅读入口。模板变化仅修正注释中闪烁任务编号 9 → 10，实际调用没有变化。

## 发现与修复

- 任务按钮原来叫「生成并排查」「编译」「写入开发板」，实际只打开相应面板，容易让学生以为已执行。统一改为「打开编译面板」「打开烧录面板」，讲义明确接着点击面板或编辑器中的实际执行按钮。
- 讲义纠正门控时钟与供电的区别、输出速度档位与闪烁周期的区别、端口内编号与封装脚号的区别，并明确 GPIO 不能直接给电机供电。
- 补充 TODO 注释替换、逐步保存、旧固件失效、错误定位及 AI 助教用法。LED 关系图说明是教学等效关系，不冒充板卡原理图。
- 远程内容烟测的小马工程夹具仍使用旧的部分工程初始化方式，缺少完整基线的 CMakeLists。为夹具接入与真实应用相同的 `sandboxSourceResolver`，重新验证完整工程构建通过；没有添加构建回退。
