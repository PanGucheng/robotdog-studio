# RobotDog Studio 双发行版教学改造总纲

更新日期：2026-08-06  
状态：当前产品演进的权威总纲；阶段一基础已于 2026-08-06 落地

## 1. 产品决策

RobotDog Studio 保持一个代码仓库、一个主分支和一套核心能力，但构建并发布两个可以分别安装的发行版本：

1. **RobotDog Studio 趣味巡线版**：面向中小学生和零基础学习者；
2. **RobotDog Studio 单片机入门版**：面向电子信息、自动化、通信等专业的大学低年级学生。

发行版在构建时确定。应用内不提供学习路径切换，新建项目时也不显示学习路径选择器。两个版本不得演变成独立代码库、长期维护分支或重复实现。

两个版本使用不同的安装身份和用户数据目录，可以同时安装。项目、设置和 AI 密钥完全隔离；现在及以后都不提供跨版本项目导入、复制或转换。

## 2. 共同架构与安全边界

- Electron Main、Preload、Renderer、候选修改、Git 存档、编译、固件产物证明和烧录保护由两个发行版共用。
- Renderer 不能选择发行版，也不能传入模板路径、权限策略、工具命令或烧录参数。
- Main 根据只读发行配置选择模板、权限、AI 提示词、构建方式、工作台功能和产品文案。
- AI 只修改隔离候选区；修改必须经过可信权限校验、编译、Diff 和用户确认后才能写入项目。
- AI 不得自动触发真实烧录。启动文件、链接脚本、Flash 分区、Bootloader、下载算法、Git 内部文件、密钥和本机敏感路径继续受到保护。
- 学习路径、学生/教师角色、模拟/真实设备状态是三个独立概念，不能合并为一个模式开关。

## 3. 发行版定义

### 3.1 趣味巡线版

- 保持现有巡线参数、CCD、简单学生代码、AI 助教、候选审核、编译、烧录、模拟设备和教师恢复体验。
- AI 使用简洁、耐心、生活化的表达，优先解释机器马动作和可观察现象。
- 只开放少量学生控制代码和参数；参考接口只读，不允许修改底层工程。
- 现有 RobotDog Studio 项目全部视为趣味巡线项目并进行兼容迁移。

### 3.2 单片机入门版

- 以 C 工程结构、编译、烧录和外设调试方法为教学重点，不以开放完整底层工程或复制 VS Code 为目标。
- AI 使用正常的 C 语言和单片机术语，首次出现术语时简要解释，并要求学生通过编译、串口或硬件现象验证。
- 可编辑范围限定在课程教学目录；启动、链接、Bootloader、下载和安全恢复相关内容保持只读或隐藏。
- 首个基础模板只建立可编译的多文件工程结构，不宣称已经提供尚未验证的 GPIO、UART 等完整课程。

## 4. 项目与数据

- 项目元数据记录固定的 `learningPath`，用于可信校验，而不是运行时切换。
- 趣味巡线版只创建和打开 `fun-line-following` 项目；单片机入门版只创建和打开 `mcu-foundations` 项目。
- 旧 v1 工作区非破坏性迁移为趣味巡线 v2 工作区，保留项目代码、Git 历史、对话历史、活动候选和固件产物。
- 迁移先备份旧元数据，再原子写入；失败时保留原数据并显式报告，不能静默删除或忽略。
- 当前“一份工作区对应一条主要 AI 历史流”可在早期继续使用；后续再将长期项目与多个 AI 对话分离。

## 5. 实施阶段

### 阶段零：审查与设计确认

- 梳理工作区、候选修改、权限、AI、编辑器、编译、固件基线、烧录、模拟设备和打包链路。
- 记录少儿巡线硬编码、可复用能力、迁移风险和最小改造边界。

### 阶段一：双发行版基础

- 建立发行配置和独立安装身份；提供趣味巡线版与单片机入门版构建命令。
- 隔离两个版本的数据目录，将旧数据安全迁入趣味巡线版。
- 项目元数据记录学习路径，Main 拒绝不属于当前发行版的项目。
- 两版分别加载模板、可信权限、AI 提示词、候选预检和工作台功能。
- 趣味巡线流程保持可用；单片机版提供真实可编译的工程结构基础模板。

### 阶段二：项目与教学工作区

- 将项目与 AI 对话逐步分离，一个项目可保存多个对话。
- 完善单片机工程树、多文件编辑、搜索、只读标识和错误跳转。
- 编译问题同时提供教学摘要与完整工具输出，安全判断仍由 Main 执行。
- 课程内容改为独立资源，不在页面中硬编码。

### 阶段三：单片机入门最小闭环

- 交付 4–6 个经过真实硬件验证的基础外设实验。
- 完成任务、编辑、编译、诊断、AI 解释、Diff、保存、固件生成、烧录和运行观察闭环。
- 增加稳定的串口文本收发、常用波特率、时间戳、清空与日志保存。

### 阶段四：课程与观察能力

- 增加程序资源变化解释、课程进度、实验记录和更多基础外设实验。
- 根据真实硬件逐步提供 GPIO、PWM、ADC、UART、传感器和机器人数据观察。
- 在基础外设稳定后增加舵机、电机、CCD、状态机和简单闭环控制实验。

### 阶段五：双版本发布

- 分别完成 Windows 安装、离线环境、工具链、驱动、模拟设备和真实硬件验收。
- 完成趣味巡线回归、单片机课程回归、安全测试、用户文档和开发交接文档。
- 两个正式安装包必须来自同一提交和同一核心版本，发行配置及教学资源可以不同。

## 6. 测试与人工复核

自动化测试覆盖类型、配置、迁移、权限、候选区、编译、产物身份和双版本打包。涉及应用实际点击、Windows 安装、驱动、串口、WCH-Link、烧录和硬件现象的验证由用户人工执行；每次交付测试包必须附带步骤、预期结果、日志位置和截图要求。

## 7. 明确不做

- 不恢复统一安装包内的双学习路径选择；
- 不支持跨版本项目导入、复制或转换；
- 不建立少儿版和大学版独立代码库或长期分支；
- 不预先开发高级嵌入式项目模式、RTOS 教学平台或通用 IDE；
- 不为了未来开发板进行脱离 CH32V203 当前需求的过度抽象。

## 8. 阶段一实施记录

本轮已建立共享发行配置、构建时版本选择、独立应用身份与数据目录、旧数据向趣味巡线版的非破坏性迁移、项目学习路径校验、双模板、双权限策略、双 AI 教学提示词、单片机多文件候选预检和双版工作台入口。两个版本仍复用 Main、Preload、Renderer、Git、构建、固件与烧录服务，没有创建长期分支或重复实现。

自动化验证覆盖类型检查、工作区 v1→v2 迁移、跨版本拒绝、候选权限与提示词约束。Windows 安装、界面实际点击、驱动、WCH-Link、烧录和硬件现象按 [双发行版人工验收清单](./dual-edition-manual-acceptance.md) 由项目所有者复核。
