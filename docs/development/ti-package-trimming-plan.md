# TI 安装包裁剪方案

日期：2026-10-21。状态：维护者已批准实施首轮裁剪，规则已接入打包流程。维护者允许不常用的 SDK 帮助链接因移除离线文档而失效。安装包不上传，线上更新清单不修改。

## 现状核对

历史提交 `2b17bce` 实施过 Git for Windows 运行时裁剪，当前 `preparePackagedGitRuntime()` 仍在使用。它不是 TI SDK 裁剪。

TI 工具链接入提交 `b2ceab8` 到当前 `226c7ef`，`scripts/package-windows.mjs` 对 SDK、SysConfig、Arm GCC、OpenOCD 都采用整目录复制，没有 TI 专用裁剪规则。`ti-mspm0-managed-toolchain.md` 也明确记录了完整复制上游目录。因此当前观察到的大体积来自现行规则，不能据此认定曾实施的 TI 裁剪被回退。

以下数字来自当前实际打包暂存目录，不是下载包体积。GB / MB 按十进制计，目录行存在包含关系，不重复求和。

| 项目 | 文件数 | 未压缩大小 |
| --- | ---: | ---: |
| TI SDK 全部 | 90,331 | 2.17 GB |
| 其中 SDK 文档 `docs/` | 44,279 | 1.23 GB |
| 其中官方示例 `examples/` | 42,339 | 478.5 MB |
| 其中辅助工具 `tools/` | 122 | 172.0 MB |
| SysConfig 全部 | 1,402 | 1.01 GB |
| Arm GCC 全部 | 5,599 | 520.2 MB |
| OpenOCD 全部 | 1,190 | 22.9 MB |

SDK 文档、示例与辅助工具合计 1,882,733,452 字节、86,740 个文件。移除三者后，SDK 剩余约 288.7 MB、3,591 个文件，尚未扣除安装日志和卸载器。安装包压缩后能减少多少、安装能加快多少，需要实测，不能按原始目录大小直接推算。

## 第一轮：本次建议实施范围

| 对象 | 拟采取的措施 | 功能边界与核验 |
| --- | --- | --- |
| SDK `docs/` | 整目录不打包 | 允许 SysConfig 中部分帮助图片、文档入口失效；Studio 自带课程、截图继续保留 |
| SDK `examples/` | 整目录不打包 | 保留 Studio 自带的 LED、基础 SDK 空工程、完整小马三套模板；逐套生成配置并编译验证 |
| SDK `tools/` | 不打包外置辅助工具 | 当前 Studio 使用独立 SysConfig、GCC、OpenOCD；不提供 SDK 自带字符识别、计量、IAR/Keil 等辅助工具 |
| SDK 安装残留 | 排除安装日志、卸载器及卸载数据 | 仅排除核实的具体文件，避免按宽泛后缀误删运行资源 |
| SysConfig 非运行文件 | 核对后排除 `tests/`、安装日志、快捷方式和卸载文件 | 保留程序实际调用的资源；不删除 GUI 自动更新组件或未知依赖 |
| SDK 源码、元数据与库 | 第一轮完整保留 `source/`、`.metadata/` 以及其余尚未确认无用的运行目录 | 含隐藏 `.meta` 目录、CMSIS、DriverLib、SysConfig 模板和组件；不只围绕 LED 程序裁剪 |
| 许可证与第三方声明 | 保留 | SDK 根许可证、第三方许可证、工具链声明及发行清单继续随包分发 |

只改变安装包资源选择，不删除或修改开发机 `D:\ti` 原始安装目录，不修改课程、学生代码、固件接口和工具链版本。

## 暂不进入第一轮的深度裁剪

- SysConfig 的 `nw/`、`app/`、`dist/`、`nodejs/`、启动脚本和兼容用 `package.json` 保留。当前 GUI 通过 NW.js 启动，CLI 使用独立 Node；两者均有实际用途。
- 暂不裁掉 `dist/deviceData/` 中其他器件的数据，避免设备查询、封装显示和切换逻辑产生隐含依赖问题。
- 暂不裁掉 Arm GCC 的其他架构库。即便界面仅面向 Cortex-M0+，也须先确认编译器自动选择的 multilib、libgcc、newlib / nano 库和 specs；不能只留 `gcc.exe`。
- 暂不更换压缩算法或提高压缩级别。先减少要复制和解压的内容，再比较包体与安装耗时；高压缩率不直接等于更快安装。
- Git 已有裁剪继续沿用；Reasonix、离线 Monaco 及后台 Worker 保留。不要为了减小包体恢复编辑器 CDN 依赖。

第一轮完成后若仍不满足安装速度，再分别评估 GCC 文档与无关架构库、SysConfig 语言包和器件数据库。每项单独测量收益并补充运行验证，不与第一轮混在一起。

## 实施方式与防回退

1. 在受版本控制的独立资源策略中定义各工具的保留 / 排除路径，由 `package-windows.mjs` 实际使用；不依赖手工清理暂存目录。
2. 为打包前后生成相同口径的体积报告：工具目录大小、文件数、最终 EXE 大小、复制 / 压缩耗时。
3. 增加资源门禁：必须存在的元数据、编译头文件、库、GUI / CLI、许可证均检查；已排除的文档、示例和辅助工具不得重新混入。
4. 更新托管工具链说明，使其不再声称完整复制上游目录。
5. 所有源码变更在正式重打包前完成并提交；从同一干净提交顺序构建 MCU / TI，保存真实 `.exe.release.json`。此前未裁剪的产物只作对比，不改写记录冒充新构建。

## 验收顺序

先生成裁剪后的隔离工具链目录并验证，再运行耗时的 NSIS 打包，避免等到压缩结束才发现缺依赖。

1. 将开发机工具链环境变量指向不可用位置，确保全程使用裁剪后的内置资源。
2. 检查固定版本、许可证与必要文件，执行 SysConfig CLI 生成。
3. 分别验证 LED 课程工程、基础 SDK 空工程和完整小马工程：配置生成、编译、链接以及 ELF / HEX / BIN / MAP 产物；覆盖候选修改编译流程与生成代码保留规则。
4. 实际打开 SysConfig GUI，验证打开现有配置、GPIO / 引脚 / 时钟界面、修改与保存，再返回 Studio 重新编译。允许缺失的离线帮助文档不算失败；配置与代码生成功能缺失算失败。
5. 完成普通测试、类型检查、课程资源校验、三个 Edition 的 Electron smoke；对最终 ASAR 执行断网编辑器检查。
6. 正式 NSIS 打包后重复内置工具链验证和三类工程编译，不以开发目录的成功代替安装包资源验收。
7. 记录 EXE 大小、未压缩体积和文件数的前后对比。在隔离 Windows 环境实测安装耗时及旧版升级后是否残留被裁掉的 SDK 文件；没有测试环境时如实标注安装耗时和升级数据保留尚未验证，不在当前电脑自动安装。

本轮不新增烧录操作，不上传安装包，不执行线上清单切换。重新打包结果记录在 [1.2.2 验收记录](../releases/1.2.2-verification.md)。
