# 全软件浅色界面与底色职责规划

日期：2026-10-14。状态：已按用户授权实施；修改与验收结果见[全软件底色统一与视觉验收](surface-system-verification.md)。以下保留当时的审查依据与规划。

后续用户调整了侧栏与导航配色：文件树、课次列表、讲义目录改为白色，公共浅蓝灰提亮，设置顶部采用导航色。当前规则以[浅色底色微调](pale-surface-verification.md)为准，以下原始规划作为调整前的记录保留。

审查基线：`d6eb34b`，并结合用户提供的工作台和讲义截图。适用于 MCU、TI、Fun 三个 Edition。承接此前浅色方向，保留品牌、页面结构、教学流程、课程状态和原生窗口控制按钮。

## 1. 现状判断

问题根源是底色没有按界面职责统一分配。上轮主要修改顶部与课程横幅，历史组件中仍有多种独立的浅灰蓝；一块完整面板的标题、正文、工具条、页脚有时又各自换色，导致视觉碎片化。

| 审查位置 | 当前实现 | 问题 |
| --- | --- | --- |
| 公共标题栏、顶部导航 | `nav-surface`；主进程窗口初始背景另写 `#f6f8fb` | 公共主题已存在，但窗口背景仍有独立来源 |
| 课程中心 | 外层 `canvas`，内层 `.course-center` 为 `#f3f6f8`，课次列表 `#eef3f5` | 同一页面出现重复的外层底色和第三种导航底色 |
| 讲义 | 白色学习页头、白色正文，目录 `.lesson-toc` 为 `#edf3f4` | 目录未复用导航角色，圆点遮罩边框还重复写了该底色 |
| 工作台文件树 | 基础规则 `#eaf2f4`；MCU 覆盖为 `#f5f8f9`；标题覆盖白色 | 同一文件导航区域上下不连续，Edition 与 CSS 层叠又改变颜色 |
| 编辑区与终端 | 编辑工具条 `#f8fbfc`；终端标签 `#f6f9fa`；输出区 `#f8fbfc`；构建操作白色 | 操作区因小块换色被切碎 |
| 实验任务与知识参考 | `.mcu-guide-pane` 为 `#f3f7f8`，固定任务头使用近似颜色的半透明背景 | 右侧教学内容被当作灰色容器，嵌套白卡片进一步增加层次 |
| AI 助教 | 浮窗白色，标题 `#f5f9fa`，紧凑聊天/讲义聊天 `#f3f7f8`，配置卡 `#f8fbfc` | 同一助教功能的不同入口缺乏统一表面规则 |
| 设置、关于、提示框 | 设置侧栏 `#f4f8fa`，标题 `#f8fafc`；提示框标题 `#edf7f8`、页脚 `#f6f9fb` | 模态窗口继续存在多种没有功能意义的底色 |
| Fun 工作台与学习中心 | 工作台 `#f7f9fb`，学习中心 `#f7fafb`、导航 `#f0f6f8`、进度行 `#f3f8f9` | 共享主题没有覆盖共享功能的其他呈现形式 |

`src/shared/studio-theme.ts` 已作为 renderer 和 Electron 标题栏的共享来源；`main.tsx` 注入 CSS 变量。`styles.css` 仍含重复声明和特定页面覆盖。Monaco 的主题在 `StudentCodeEditor.tsx` 中单独定义，属于需要同步检查的边界。

上轮几何检查与功能测试结果仍是当时执行记录，但不足以证明整个软件底色一致。本轮验收增加区域角色与最终计算样式检查。

## 2. 固定三种基础表面

不继续扩充近白色调色板。基础表面固定为三种，按职责而非组件名称分配。

| 角色 / 拟定 Token | 颜色 | 使用位置 | 使用约束 |
| --- | --- | --- | --- |
| 页面留白 `surface-page` | `#F5F8FA` | 首页、课程中心、独立工具页等内容块之间的外围留白 | 不用于面板内标题、输入框、终端、任务正文；贴边工作台可不露出此色 |
| 应用导航 `surface-navigation` | `#EAF2F6` | 原生按钮区、自定义标题栏、全局导航；课次列表、讲义目录、文件树、设置分类、学习中心目录 | 同一导航区域标题、列表、固定底部说明保持连续；普通行透明，不嵌入一组独立白卡片 |
| 内容表面 `surface-content` | `#FFFFFF` | 横幅、讲义、编辑工具条、浅色编辑器、终端、任务说明、知识参考、AI 对话、菜单、弹窗及内容卡片 | 标题、正文、工具条、页脚通常同色，用细线和间距分区；不再逐行交替浅灰背景 |

**导航的定义**：主要用于选择页面、课次、章节、文件或设置分类的持续区域。实验任务中的说明、进度和操作属于教学内容；终端标签属于内容区内部切换；浮窗标题属于浮窗自身。因此不因为某个元素是 `nav` 或 `header` 就自动使用导航底色。

**连续表面的定义**：一个文件树或内容面板内的默认底色保持一致。选中项、局部状态提示、代码当前行等有明确意义的局部强调可以使用专门状态色，不构成第二种默认底色。

## 3. 文字、交互与边界

| 用途 | 拟采用规则 |
| --- | --- |
| 主文字 / 品牌 | `#142F46`，沿用现有字体与 Logo |
| 正文 / 次级说明 | 正文优先主文字；说明统一 `#526B7A`，避免历史浅灰文字影响小字号阅读 |
| 主操作 | `#07788A` + 白字；hover/pressed 使用同一套更深强调色 |
| 选中导航行 | 专用 `surface-selected: #DFF3F6`，配深青文字、细边框或左侧指示；课程列表、目录、文件树、设置分类统一规则 |
| 默认 hover | 专用 `surface-hover: #DCEAF0`，仅显示在可交互对象上；不作为整块面板底色 |
| 焦点 | 明确青色描边，独立于 hover 和 selected；保留键盘可见焦点 |
| 默认按钮与输入框 | 白色或透明，依据所在表面；边框区分可编辑控件，默认不借用页面底色 |
| 状态 | 保留黄课次编号及绿/黄/红状态；局部提示使用对应状态 Token、图标和文字，不整块染色 |
| 分区边界 | 优先 `#D8E3EA` 的 1 px 细线和间距；区域内部无需重复圆角卡片 |
| 圆角 / 阴影 | 延续现有尺度并统一同类控件；主面板弱化阴影，浮层保留必要层级阴影 |

普通文字对比度至少 4.5:1，大字号至少 3:1；操作边界与焦点标记按实际相邻表面核验。禁用状态仍应能读出标签，并使用实际 disabled 行为。黄色、绿、红等状态不只靠颜色表达。

## 4. 每个页面的最终结构

| 页面 / 场景 | 最终默认底色结构 | 具体收敛内容 |
| --- | --- | --- |
| 公共窗口与导航 | 上方连续导航色；页面内容按自身职责 | 标题栏、原生按钮区、全局导航同步；菜单白色；删除没有必要的独立控件底块，检查长课程名与 TI 品牌副标题 |
| 首页 / 自由练习 | 外围页面色 + 白色入口和项目卡 | 卡片不再半透明混入底色；简介区域不新增有色横幅；最近项目、创建入口按同类规则处理 |
| 课程中心 | 页面色外围 + 白色简介 + 导航色课次列表 + 白色详情 | 外层与内层页面底色一致；横幅保持紧凑；左栏普通行透明，当前课统一选中态；详情中的次要信息不各自加灰底 |
| 课程学习 | 白色学习页头 + 导航色目录 + 白色阅读区 | 目录底色与其他导航统一，目录标题和轨迹遮罩同步；当前章节使用统一选中态；正文、图片与阅读宽度保留 |
| MCU / TI 工作台 | 导航色文件树 + 白色编辑/终端区 + 白色实验任务区 | 文件树标题/正文/底部安全说明连成一块；编辑工具条、终端标签/工具条/输出/构建操作同色；右侧头部与任务说明同色 |
| 自由工程工作台 | 导航色文件树 + 白色编辑/终端区 | 新建文件、只读文件、修改标记、编译等状态遵循相同规则，不按工程类型另设背景 |
| 实验任务 / 知识参考 | 白色教学表面 | 固定头部使用不透明白色；步骤间靠细线与间距组织；保留当前步骤、完成和未连接提示，减少卡片内再套卡片 |
| AI 助教 / AI 历史 | 白色浮窗、标题、对话与输入区 | 讲义和工作台入口一致；配置和修改建议默认白色；必要消息、代码块及权限/失败状态局部强调 |
| 设置 | 白色标题/内容 + 导航色分类 | 分类区连贯；更新、AI、硬件、高级设置按同一控件与状态规则呈现 |
| 关于 / 确认 / 重命名 / 导览 | 默认白色内容表面 | 普通模态标题与页脚不换底色；关于页作为页面时可保留页面色外围、白色内容块，作为弹窗时不为每小节增加一层灰底 |
| Fun 工作台 | 页面色外围 + 白色工具内容；工具标签沿用内容表面 | 依次检查参数、CCD、串口、构建、WCH-Link、代码、修改确认；学习中心为导航色目录 + 白色教学内容 |
| 修改确认 / 烧录 / 更新 | 白色外围和操作区 + 有功能意义的专用内容主题 | 对比代码、构建日志、波形/图表颜色单独核验；不把增加/删除或采样数据语义改成普通表面色 |
| 空状态 / 加载 / 失败 / 窄窗口抽屉 | 继承所属区域的角色 | 抽屉打开后文件树仍为导航色、任务区仍为白色；状态变化不切换整个页面默认底色 |

代码与功能日志中的现有深色主题是明确例外；保留语法、diff、波形等语义。现有浅色 Monaco 背景继续白色，当前行/选区使用编辑器状态规则。

禁止按颜色值全局替换：同一个值可能出现在选区、图表、状态或普通容器中。先确定角色，再修改对应声明。主题注入、测试环境和 CSS 默认值不得各维护一套独立颜色；实现时选择共享导出/生成方式，保留现有构建体系。

不改课程内容、课次数据、AI 行为、硬件交互、固件或软件版本。不引入新 UI 框架，也不进行全组件重构。

## 6. 实施顺序与验收

1. **固定角色并处理公共层**：主题、窗口、导航、菜单、按钮与焦点。建立最终生效 Token 的检查入口。
2. **完整主教学链**：首页 → 课程中心 → 讲义 → 实验工作台。先按整屏观察，随后核对文件树、终端、任务栏每个子区域，而不是只看课程横幅。
3. **处理跨页功能**：AI 两个入口及历史、设置、关于、提示框、自由工程和 Fun 工具；核对空状态、错误、禁用和抽屉形态。
4. **统一审阅后完成验证**：同 Edition 多页面并排检查，再跨 Edition 检查；反馈引起的新改动重新检查对应场景。

### 视觉验收矩阵

- 三个 Edition 的公共导航和可用主要页面；工作台同时检查文件树、工具条、编辑器、终端、任务/参考区。
- 100%、125%、150%、175% UI 缩放，普通、较窄和最大化对应内容尺寸。代表性场景包括长课名、长路径、长项目名和较大字号。窄窗口允许规定的抽屉与纵向滚动，不能丢失入口或把导航挤到按钮下。
- 默认、hover、selected、键盘焦点、disabled；未修改/已修改、终端收起/展开、未编译/编译中/失败/成功；未连接硬件提示；AI 未配置、历史/回答/修改建议；弹窗取消/输入/提交失败。
- 测试通过已有隔离数据和可控状态构造覆盖，不为截图调用真实 AI、升级或烧录，也不把构造状态当作真实硬件验证。
- 同一个区域默认态的标题、正文、页脚实际计算底色一致；导航区域只用导航 Token，页面色只出现于外围；有语义的状态区域列为例外清单。
- 检查正文、小字、按钮、选中项、提示文字对比度；焦点不被裁切；代码、正文、图片与日志可以正常滚动。

### 验证方法与交付

优先沿用隐藏 Electron 测试窗口，不切换用户桌面焦点。采集真实 renderer 原始像素无损 PNG，同时保存场景、尺寸、缩放和最终计算样式记录。提供整屏并排图与必要局部原图；拼图不能代替清晰原图。隐藏窗口不能证明 Windows 原生按钮点击、拖动或系统贴靠正常，需在适合的手动验证环节单独报告。

实现后执行类型检查、生产构建、适当组件/功能测试、三个 Edition 的 Electron smoke，并核对课程校验未受影响。现有 `package.json` 提供 `pnpm typecheck`、`pnpm build`、`pnpm exec vitest run --maxWorkers=2`、`pnpm smoke:electron:mcu` / `:ti` / `:fun`、`pnpm courses:validate`。按需要组合命令避免重复构建；本次规划阶段没有重跑这些测试。

最终交付包括实际修改文件、最终 Token、逐页面和状态检查结果、测试结果、前后同场景截图及尚未手动验收的边界。此前课程教程内的截图保持原始教学资料；若导航外观变化影响找入口，再单列需更新的截图清单，不为视觉任务自动改课程版本。

**完成标准**：学生在切换页面时可以稳定识别导航、教学内容和状态；一块完整区域不再因为标题、工具条、正文、页脚而反复换浅色背景。通过功能测试只是必要条件，整屏视觉复核同样必须通过。
